## 背景

工程实战需要可复核的任务、CI 与人工控制。

## 保留的决策

Issue → Agent → Draft PR → 人工合并。

## 替代方案与取舍（源基准）

直接改主分支风险高，先自研 Agent 不必要；采用成熟 Agent 及平台强制审核。

## 影响与实施约束

分规格唯一入口：[相关规格](../development/AI-WORKFLOW.md)。本 ADR 不添加源文件之外的功能；数值不是实测结论。相关待决议：D15 部署环境，详见 [开放决议](../development/OPEN-DECISIONS.md)。依赖未关闭前只能实施不受影响部分。

## 验证与重新评估

验证：失败检查阻止合并、证据完整、授权后才能部署。对应 [M0-04](../development/issues/M0-04.md)，实际执行证据在后续 PR 中提交。

当现有方案不能满足已确认需求，或新增功能确实需要突破边界时，提出新 ADR 说明证据、替代方案、存档/回放/版本影响及迁移成本。人工确认前保持现有基准；不能为局部实现方便默默推翻决策。
