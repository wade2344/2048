# 数值平衡 BALANCE

> 文档版次：0.1.0-docs.1 · 2026-11-25 · Phase 0 文档交付；游戏尚未实现。
> 来源：[输入基准](../reference/SOURCE-BASELINE.md)；对应章节 / 说明：11.1、11.3–11.4。
> 效力：仅 PRD 明列项为用户已确认；其余沿用设计基准。本文新增接口细化、测试设计、任务拆分属于交付建议；所有初始数值待模拟与试玩验证。
> 待决议建议没有生效；受影响规则落地前须关闭对应 [D 项](../development/OPEN-DECISIONS.md)（验证型门按登记说明执行）。

## 设计目标（均待验证）

- 新手整轮通关率 10–20%；普通玩家 30–50%；熟练玩家 60–80%。Bot 与真实玩家通关率不可直接等同。
- 原讨论普通玩家单关条件通过率示例：99%、95%、92%、87%、78%、70%。该组合的累计通过率约 41%，与整轮目标一致。
- 单轮 15–25 分钟；拥有主动技能且可使用的关卡，每关约 2–8 次主动技能（第 1 关无技能，不适用）。不同流派通关率差距尽量控制在 15 个百分点内；须说明流派定义、样本量、技能取得时点及选择偏差。
- 第一、二关容易，后半段难度递进，Boss 不应比第五关明显容易。

## 数据与实验基准

记录关卡进入人数/通过率/步数/失败位置/最大数字；技能出现率、选择率、使用次数、取得关卡、搭配；词缀通过率及失败原因；EP 获取、消费、平均剩余及溢出；Boss 伤害来源、击杀步数、攻击命中率；异常/超限数、策略版本与种子集合。报告需区分条件通关率与整轮通关率。

定向超频对照：A=6 EP，B=7 EP，C=8 EP，D=6 EP 但目标不超过 64。使用相同种子集合、同版 Bot 与策略参数，比较通关率、置信区间、选择/释放次数、取得时点、其他技能组合；分别分析已持有该技能的对照样本。不能把持有通关率直接当成因果效果。原讨论的 64%、53%、43%、38% 等图表为虚构演示数据，不属于测试结果。

高优先级：定向超频/回滚/障碍死局（P0）；第五关 256 难度断层、第三关 300 分、Boss 1000 HP、能量回收循环（P1）；矩阵重构价值、生存 40 步趣味（P2）。CLI 和 JSON 报告先行，开发环境 /dev/balance 可视化后续实现，展示条件通过率、流派、EP 和异常提示。

## 人工试玩

验证前两关易懂、期待奖励、三选一有真实取舍、技能使用频率合理、无明显废技能、词缀改变决策、失败原因可解释、Boss 预告有效、高阶合并有成就感、失败后愿意尝试其他构筑。重要发布先做 5–10 局人工试玩，并根据经验层级记录样本；不把小样本当作总体通关率。

## 参数与变更控制

所有数值来自输入基准；不在拆分过程中调参。关卡 32/64/300/40/256、Boss 1000 HP、EP 4/10、12 技能成本与阈值、词缀强度、攻击周期、生成概率、Bot 权重均为待验证初值。参数唯一权威表分别位于 LEVELS、SKILLS、PROTOCOLS、BOSS；实现后集中由 game-config 提供，UI 不复制数值。

数值调整 Issue 必须包含：假设、基线/候选配置身份、共同种子集、Bot 版本与参数、原始报告、样本量/区间、人工试玩记录、是否采纳及理由。更改配置也可能使旧回放不兼容，不能只在 PR 中称为「文案调整」。

建议初期报告保留所有失败/异常类别；不以胜率接近目标替代正确性。设计目标与实测结果分栏，未运行时写「未运行」，不填零或演示数字冒充结果。参见 [模拟规格](../architecture/SIMULATION.md)。
