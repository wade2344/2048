### 7.1 首版（用户已确认 A，以下参数是设计初值）

| 属性 | 设计基准 |
|---|---|
| Boss HP | 1000 |
| 玩家 HP | 无 |
| 伤害 | 每步合并基础分数 + 本步技能额外分数 |
| 攻击 | 区域封锁 GRID LOCK |
| 间隔 | 每 5 次有效移动 |
| 预告 | 提前 2 步标记固定格子 |
| 持续 | 锁定 2 次后续有效移动 |
| 初始状态 | 新棋盘，继承五个已获得技能，4 EP / 10 EP |
| 随机词缀 | 无 |
| 胜利 | HP ≤ 0，立即结束冒险 |
| 失败 | 棋盘无合法移动且无可用救场能力 |

示例：同一步 4+4、16+16、64+64，基础 8+32+128=168，若拥有并行运算则额外 84，总伤害 252；连续运算满足条件时再加 32。定向超频本身不造成伤害。伤害不得使实际 HP 低于 0；显示值与统计规则需区分实际扣血及溢出伤害。

### 7.2 区域封锁

攻击的是固定棋盘格子而非追踪方块 ID，提前预告可让玩家转移高阶方块；结算时目标为空则落空。目标有普通方块时临时锁定，无法移动、合并、被普通主动技能选中，原数值保留；计满两次后续有效移动后解锁。无效滑动与主动技能不推进攻击时钟。

保护规则：若当前原本存在合法滑动，而新增封锁将立刻导致无合法滑动，则取消此次封锁。若本次合并已击败 ZERO，不再进行随机生成/后续攻击。状态回滚恢复 HP、计时、预告目标、锁定状态、RNG 与结算结果。紧急重启只处理未锁定普通方块。

### 7.3 演进至 D

V1.1 增加能量干扰、数据污染、数字降级等攻击；V1.2 根据剩余生命值进行阶段转换（此前曾讨论 70%/30% 阈值，仅为未来草案）；V1.3 加入护盾、弱点与指定解谜目标；V2.0 引入玩家 HP、攻防、阶段切换和更多策略。首版不得提前实现玩家 HP、护盾、狂暴、多攻击或多阶段状态机。

## 同步事务和封锁验收

1. 校验并执行有效移动、普通合并、分数与 EP 结算；计算该步伤害。
2. 若 HP 已降至 0，提交冒险胜利，取消本步后续普通生成与 Boss 攻击。
3. 未击杀时继续普通生成、封锁更新、Boss 行动及救场/败局处理。阶段内精确顺序属于 D03/D09。
4. 完整事务提交后统一记录和保存；UI 仅播放事件。

上述击杀优先分支是源基准明确规则，不随 D02 的普通关判胜选择而变化。锁定影响原方块但攻击目标是格子，不能把预告实现为追踪 ID。

第 3 步预告/第 5 步攻击/第 7 步后解锁是 D09 的候选时间线，尚未获准；测试用例须在决议后固定。特别是已有锁定导致无合法移动时，不能让倒计时等待一个不可能发生的有效步。

真实扣血与溢出伤害的统计分离见 D19；显示 HP 始终不低于 0。伤害示例 168→252 保留，不能用词缀倍率扩展 Boss，因为本关无环境词缀。

验收见 [BS-01–06](../development/TEST-CASES.md)；回滚复原 Boss、预告和 RNG 见 [SAVE-REPLAY](../architecture/SAVE-REPLAY.md)。
