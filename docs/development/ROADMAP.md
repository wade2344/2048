> 效力：仅 PRD 明列项为用户已确认；其余沿用设计基准。本文新增接口细化、测试设计、任务拆分属于交付建议；所有初始数值待模拟与试玩验证。
> 待决议建议没有生效；受影响规则落地前须关闭对应 [D 项](OPEN-DECISIONS.md)（验证型门按登记说明执行）。

## Phase 与 Milestone 的对应

Phase 0：本次文档拆分与验收，不实现代码；覆盖 M0-02/03 的文档草案，但未完成真实仓库入库、平台配置或人工接受。

Phase 1：经后续明确授权后初始化工程与 CI（M0-01/04 等）。Phase 2：使用成熟 Agent 跑通一个真实小 Issue→Draft PR→人工验收闭环，再持续按 M1–M8 实现。Phase 2 是工作流阶段，不等于 M2 游戏关卡里程碑。

## 产品版本与验收范围

| 产品版本 | 工作包覆盖建议 | 限制 |
|---|---|---|
| V0.1 | M0–M1 | 经典可玩，不声称完整 Roguelike |
| V0.2 | M2 + M3-01 | 关卡/奖励/共享 EP，不声称 12 技能全可用 |
| V0.3 | M3–M5 | 12/12/6 与 ZERO，完整数据 UI 尚未完成 |
| V0.4 | M6–M7 | 存档回放、三 Bot 与数值报告 |
| V1.0 | M8 | 人工验收后的 H5 发布 |
| V1.x / V2.0 | 独立未来 Issue | Boss A→D、Expectimax、开发者面板，不混入首版 |

本表是交付顺序建议，不承诺日历工期。实际顺序以 [任务 DAG](BACKLOG.md) 为准；任何开发开始前检查范围内 D 项，不能以阶段名称宣称依赖已完成。

## M9 小程序版

2026-11-26 新增需求。在主体玩法完成后交付小程序版本。以下启动节点和技术路径为排期建议，目标平台待确认。M9 可与 M7、M8 并行。

| 步骤 | 开始条件 | 工作与验收 |
|---|---|---|
| M9-01 真机样机 | M5 六关可玩，明确目标平台和应用形态 | 引入同一引擎及配置，跑通滑动、合并动画和一次保存恢复。在一部目标设备记录操作延迟、加载时间和适配问题，据此估算余量。若选微信，先确认普通小程序或微信小游戏的发布路径。 |
| M9-02 完整体验版 | 样机通过，M6 存档与回放契约稳定 | 适配准备页、奖励、技能选取、Boss 预告、结算及回放。用同一规则版本、种子及动作日志比对 H5 与小程序逐步状态，覆盖棋盘、EP、候选奖励及 Boss 状态。在真机验证切后台、关闭再打开后继续游戏。 |
| M9-03 正式发布 | 体验版通过，发布账号与平台要求已核实 | 在目标设备矩阵试玩六关，记录性能和缺陷。由项目负责人验收体验版并授权提审，记录审核结果、线上可访问版本与回退方式。 |

开发期间将触摸输入、渲染动效、存储、前后台切换和回放文件操作保留在客户端层。平台选择与真机测试完成后，再决定具体渲染和文件交换方案。
