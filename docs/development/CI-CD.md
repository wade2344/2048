## 源基准

建议根脚本：dev、lint、typecheck、test、test:coverage、test:e2e、build、check、simulate、balance:compare。check 至少执行 lint、typecheck、test、build。脚本均为规划，尚未实现。

GitHub Actions：PR 创建/更新时锁定依赖安装，执行 lint、typecheck、Vitest、build、Playwright、100 局快速模拟（相应模块完成后启用）。游戏规则变更 PR 做 1000 局数值对照；完整 10000 局手动/定期运行；重要发布人工试玩。规则错误、崩溃、确定性失败、CI 失败阻止合并；数值指标早期只生成供审阅的对比报告，稳定后经人工批准再增加阈值。不得为过 CI 删除测试或擅改标准。使用 GitHub Rulesets/分支保护与 required checks；实际可用性依据仓库和权限核实。主分支只能人工验收后合并，CI 部署 H5 静态产物，部署目标待 Phase 1/发布决定。

## 逐步启用门禁（不是本阶段执行结果）

| 阶段 | 启用检查 | 不能伪装通过的情况 |
|---|---|---|
| Phase 1 / M0 | 依赖锁定安装、lint、typecheck、真实最小测试、build | 尚无业务测试时不得声称规则验收通过 |
| M1–M3 | 引擎单测、确定性、技能回归、已具备的交互 E2E | 不能把暂缺规则的空断言作为绿色检查 |
| M4–M6 | 词缀/Boss/六关 E2E、版本与存档回放、回滚回归 | D 项未关闭不能冻结与其冲突的期望 |
| M7 | 每 PR 100 局快速模拟；规则变更 1000 局对照 | 超限/崩溃/非法动作分类；不能把未运行写成零异常 |
| 发布前 | 10000 局完整模拟（手动/定期）、5–10 局起人工试玩、M8 兼容性能 | 目标胜率不是测试通过证据 |

正确性硬门禁：确定性、非法状态、运行崩溃、适用必需检查失败应阻止合并。早期平衡数据只生成审阅报告，后续阈值需明确批准并版本化。

建议部署链路为人工合并后构建同一提交的静态产物，记录版本及产物摘要；部署目标/权限/回滚方案由 D15 与 M8-03 明确。此包不包含 workflows YAML，不创建定时自动化，也不进行发布。
