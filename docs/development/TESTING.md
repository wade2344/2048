# 测试策略与验收规范

> 文档版次：0.1.0-docs.1 · 2026-11-25 · Phase 0 文档交付；游戏尚未实现。
> 来源：[输入基准](../reference/SOURCE-BASELINE.md)；对应章节 / 说明：12.1。
> 效力：仅 PRD 明列项为用户已确认；其余沿用设计基准。本文新增接口细化、测试设计、任务拆分属于交付建议；所有初始数值待模拟与试玩验证。
> 待决议建议没有生效；受影响规则落地前须关闭对应 [D 项](OPEN-DECISIONS.md)（验证型门按登记说明执行）。

| 层级 | 验收范围 |
|---|---|
| Unit | 四方向、一次合并限制、空位、障碍、锁定、非法输入、EP、奖励、各技能、词缀、关卡目标与 Boss |
| Determinism | 同 Seed/Action 完全一致；无效操作不推进 RNG；子流隔离；ID 复现；跨关与规则版本 |
| Integration | 技能和词缀兼容、顺序、上限/溢出、救场、回滚与 Boss 状态、奖励幂等、存档恢复 |
| E2E | 桌面/移动输入、六关闭环、奖励选择、刷新恢复、终局、回放隔离、取消技能不扣费 |
| Simulation | 崩溃、非法状态、超限、合法操作与平衡数据回归；不将超限混入正常败局 |
| Manual | 视觉、连续输入、不同屏幕、减少动画设置、策略乐趣及数值体验 |

专项断言：存档恢复 RNG 一致；刷新不改变奖励/词缀/攻击目标；回滚恢复完整状态且不刷 EP；损坏存档被检测；不兼容回放拒绝；回放最终状态一致且不改变实际存档。对死局、生成额外方块无空位、锁定目标为空、击杀与攻击同一步、能量恰好够/不足、重复选择奖励、跨关重置、最高值及全棋盘均需边界覆盖。



## 测试设计与执行证据

详细 Given/When/Then 见 [TEST-CASES](TEST-CASES.md)，逐技能 SK-01–12、逐词缀 PT-01–12 不能省略。每个 Issue 对应可定位的用例或专门验收步骤；测试文件名和执行命令在实现时填写，不在 Phase 0 虚构路径或绿色结果。

| 契约 | 必测边界 | 证据要求 |
|---|---|---|
| 不可变性 | 嵌套棋盘、计数器、候选、RNG、undo | 深冻结输入测试；拒绝动作全状态比较 |
| 确定性 | 同 Seed/版本/成功序列、四流隔离、恢复 | 参考向量与规范逻辑状态快照；排除墙钟等元数据 |
| 技能/词缀 | 精确足额/不足、目标非法、周期前/到/后、溢出 | 每项正向/反向/边界；相互作用回归 |
| 救场 | 满盘仍可动、无合法 MOVE、已有锁定、主动可用但无效 | D08/D09 关闭后固定反例，防无限等待 |
| 存档/回放 | 所有稳定 phase、损坏/过大/未知版本、回滚轨迹 | 正常存档前后比对；错误步号；恢复 RNG 完全一致 |
| UI | 快速输入、选择取消、终局缓存、减少动画 | 可重复 E2E 与人工设备记录 |
| 数值 | 真实共享引擎、固定 seeds、异常分母 | 原始 JSON 与比较报告；不据单一胜率断言平衡 |

## 组合覆盖与优先级

优先 P0：回滚资源/标志、定向超频目标、障碍/锁定死局、状态恢复、RNG 泄漏。P1：并行+运算加速、能量回收+极限超载、指令税/压缩+回滚、预载+初始化词缀、周期事件+通关、手动救场+自动救场。P2：布局、动效、报表展示等体验细节。

不要求穷举全部构筑后才开发；先覆盖每项效果和高风险组合，再用固定种子模拟补充。统计抽样测试不应把样本比例恰好等于配置概率作为确定性断言。已确认边界用精确期望，未决边界用决议门而非宽松的任意答案。

## 完成定义

依赖和规则决议已满足 → 本 Issue 的正向/反向用例通过 → 适用集成/E2E/模拟通过 → 文档和版本影响更新 → Draft PR 提供实际结果 → 人工验收。未执行检查写「未执行及原因」，失败写实际失败；不得标记不适用来掩盖缺失实现。

本阶段仅验证 Markdown 文档、来源覆盖、依赖图、链接、归档和数量。没有运行游戏单元测试、E2E、构建或模拟，也没有数值平衡结论。
