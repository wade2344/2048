## 统一冲突登记口径

| 发现的潜在冲突 | 本包处理 | 不得误解为 |
|---|---|---|
| 普通关生成后检查 vs Boss 致死立即结束 | 两个原基准分支明确标识，普通关保留 D02 | 已统一选择某一新流程 |
| 完整回滚 vs 紧急重启整轮一次 | 两条均保留，D10 待人工裁决 | 默认可/不可恢复标志 |
| 固定生成 4 vs 高阶生成 30% | D06 记录覆盖与排除候选方案 | 默认废弃高阶生成 |
| GameSave 顶层 RNG vs GameState RNG | 草案保留且注明单一真源要求，D11 定结构 | 可以两处独立维护 |
| 封锁持续有效步 vs 已无法有效移动 | D09 明列无解等待风险 | 自动提前解锁已经获准 |
| 候选准备页显示 vs ENTER_LEVEL 才初始化 | D18 固化抽取/初态责任 | 刷新后重新抽取合法 |
| 普通技能无收益 vs 回滚恢复历史字段 | 将回滚定义为特殊恢复动作 | 回滚不能恢复分数/步数 |
| 原工作包粗依赖 M0/M1–5 | 展开为显式无环任务图；保留原前置列 | 更改产品范围或已执行任务 |

除明确的源基准规则外，所有建议均须决议后才能作为实现期望。Phase 0 的通过标准允许待决议存在，但要求可定位、可追溯、可阻塞相关开发。
